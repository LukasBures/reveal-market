PROJECT: Reveal Market – Smart Contract Module
VERSION: v1.0
---
1. Scope
Implement smart contract components required for MVP on Horizen EVM Testnet: MarketFactory, RevealMarket, RakeManager, Verifier. Deliver up to settlement and claim flow (commit → lock → result → verify → claim).
Focus on Solidity ^0.8.24, gas-optimized, modular, testable.

---
2. Components
2.1 MarketFactory.sol
• Deploy new markets via EIP-1167 minimal proxies (Clones).
• Store implementation address, list of deployed markets.
• Admin functions: setImplementation, setRakeManager, setTreasury.
• Event: MarketCreated(address market, string eventId, uint256 commitDeadline, uint256 revealDeadline).
2.2 RevealMarket.sol
• Phases: enum Phase { Commit, Locked, Settled }.
• Storage: commitDeadline, revealDeadline, oracle, verifier, rakeManager, totalPool, winningPool, winningOutcomeHash.
• Mapping: userTickets[address => Ticket[]], where Ticket { bytes32 commitHash; uint256 amount; bool revealed; bool claimed }.
• Functions: commit(bytes32 ticketHash) external payable onlyPhase(Commit); lock() external onlyAfter(commitDeadline); postResult(bytes32 outcomeHash) external onlyOracle; verifyProof(bytes calldata proof, uint256[4] calldata pubSignals) external onlyPhase(Locked); claim(uint256 ticketId, string calldata outcome, bytes32 salt) external onlyPhase(Settled); refund() external onlyAfter(revealDeadline) ifNotSettled.
• Events: Committed(address user, bytes32 ticketHash, uint256 amount); Locked(); ProofVerified(bool success); Settled(bytes32 winningOutcomeHash); Claimed(address user, uint256 payout); Refunded(address user, uint256 amount).
• Integrations: RakeManager.takeRake; Verifier.verifyProof.
2.3 RakeManager.sol
• Storage: treasury address, rakeBps (uint256, max 200).
• Functions: setRakeBps(uint256 newRate) onlyOwner; setTreasury(address newTreasury) onlyOwner; takeRake(uint256 amount) external returns(uint256 netAmount).
• Event: RakeTaken(uint256 totalAmount, uint256 rakeAmount, address treasury).
2.4 Verifier.sol
• Function: verifyProof(bytes calldata proof, uint256[4] calldata pubSignals) external returns(bool).
• For MVP: stub implementation returns true and emits event ProofChecked(bool success, address sender).
• Future: replace with auto-generated Groth16/Noir verifier.

6. Security & Compliance
• Use ReentrancyGuard on claim & refund.
• Use SafeTransferLib for ETH/native ZEN and ERC20 transfers.
• Deadlines based on block.timestamp.
• Oracle address and treasury address immutable after deployment.
• Owner/admin functions only - use Ownable2Step pattern.
• RakeBps cannot exceed MAX_RAKE_BPS constant (e.g., 200 = 2%).
• Document privacy model: only outcome hash revealed pre-settlement; ticket amounts and user data remain private until claim.

7. Deployment Sequence
1. Deploy RakeManager with treasury address and default rakeBps.
2. Deploy Verifier stub.
3. Deploy MarketFactory with implementation address (initial RevealMarket logic) and reference to RakeManager.
4. For each market: Factory.createMarket(eventId, commitDeadline, revealDeadline, oracleAddress).
5. Market contract goes to commit phase.
6. After commitDeadline: anyone calls market.lock().
7. Oracle posts outcome via market.postResult(winningHash).
8. Market calls verifier.verifyProof(proofData, pubSignals) → transitions to Settled.
9. Users claim via market.claim(ticketId, outcome, salt).
10. Treasury rake transferred via RakeManager during settlement.

2.1 MarketFactory.sol
• Purpose: Factory contract to deploy and manage RevealMarket instances using EIP-1167 minimal proxy pattern (Clones) for gas-efficient deployment. Enables scalable creation of markets with standardized logic and centralized management of implementation, treasury, and rake manager references.
• State Variables:
  - address public implementation; // Address of RevealMarket logic contract used for clones
  - address public rakeManager; // Address of RakeManager contract managing fees
  - address public treasury; // Address receiving rake fees
  - address[] public markets; // Array of deployed RevealMarket clone addresses
  - mapping(address => bool) public isMarket; // Quick lookup for deployed markets
• Functions:
  - constructor(address _implementation, address _rakeManager, address _treasury) public
    - Sets initial implementation, rakeManager, and treasury addresses. Reverts if any address is zero.
  - function setImplementation(address _implementation) external onlyOwner
    - Updates implementation address. Reverts if zero address.
  - function setRakeManager(address _rakeManager) external onlyOwner
    - Updates rakeManager address. Reverts if zero address.
  - function setTreasury(address _treasury) external onlyOwner
    - Updates treasury address. Reverts if zero address.
  - function createMarket(string calldata eventId, uint256 commitDeadline, uint256 revealDeadline, address oracle) external onlyOwner returns (address)
    - Deploys a new RevealMarket clone using Clones library pointing to implementation.
    - Initializes clone with parameters: eventId, commitDeadline, revealDeadline, oracle, rakeManager, treasury.
    - Stores clone address in markets array and sets isMarket mapping.
    - Emits MarketCreated event.
    - Reverts if deadlines invalid (commitDeadline >= revealDeadline or deadlines in past), or oracle is zero address.
  - function getMarkets() external view returns (address[] memory)
    - Returns list of all deployed market addresses.
• Events:
  - event MarketCreated(address indexed market, string indexed eventId, uint256 commitDeadline, uint256 revealDeadline);
    - Emitted upon successful deployment of a new RevealMarket clone.
• Security and Deployment Notes:
  - OnlyOwner modifier restricts administrative functions to factory owner.
  - Implementation contract must be trusted and immutable after deployment to prevent logic tampering.
  - Treasury and RakeManager addresses are critical for fee management and must be carefully set.
  - Clones pattern minimizes gas cost per market deployment, enabling scalable market creation.
  - Factory maintains authoritative registry of deployed markets via markets array and isMarket mapping.
  - Input validation on deadlines and oracle prevents misconfiguration and potential locking issues.
